# WHAM Quick Replies — канонический Workboard

## Каноническая точка разработки

- Репозиторий: `Vutovk31/WHAM`.
- Единственная рабочая Git-ветка: `main`.
- Единственная поддерживаемая архитектура: нативное C# WinForms-приложение в `src/WHAM.QuickReplies.Native`.
- Параллельные продуктовые ветки, старые PowerShell/CMD/VBS-сборки и прежний installer не развиваются и не возвращаются в продукт.
- Любая работа WHAM, не относящаяся к локальным текстовым макросам, остановлена до отдельного решения.

## Зафиксированный объём продукта

WHAM Quick Replies — локальное Windows-приложение исключительно для текстовых макросов:

`macros.json` → глобальная горячая клавиша → вставка многострочного Unicode-текста в активное поле Windows.

Разрешённый объём:

- создание, редактирование и удаление текстовых шаблонов;
- локальное хранение в JSON;
- назначение и перезагрузка глобальных горячих клавиш;
- вставка Unicode-текста в активное поле;
- системный трей;
- резервное копирование и диагностика;
- portable/release packaging.

Исключены OCR, захват экрана, AI, облако, CRM, KPI, звонки, SEO и любые другие модули.

## Текущая версия

- Целевая тестовая версия: `0.10.0-native-test1`.
- Формат поставки: versioned portable ZIP для Windows x64.
- Версия должна совпадать в имени ZIP, корневой папке архива, `VERSION.txt`, UI/About и SHA256-файле.

## Текущий приоритет

Порядок приёмки фиксирован и не расширяется до завершения текущего цикла:

1. Компилируемый `0.10.0-native-test1`.
2. Успешный Windows GitHub Actions build.
3. Versioned ZIP и SHA256.
4. Запуск EXE на реальном Windows-компьютере.
5. Значок приложения в системном трее.
6. Блокнот → `Ctrl+Alt+1` → корректная вставка текста.
7. Изменение `macros.json` или редактор → перезагрузка горячих клавиш.
8. Перезапуск приложения без потери пользовательских данных.

## Что уже реализовано в CI

Workflow `.github/workflows/build-native-portable.yml` выполняет:

- проверку native-исходников на запрещённые script/launcher-паттерны;
- restore, build и self-contained publish под `win-x64`;
- deterministic `--self-test` опубликованного EXE;
- startup smoke-test EXE;
- создание versioned ZIP;
- вычисление SHA256;
- проверку состава и версии архива;
- публикацию ZIP и SHA256 как GitHub Actions artifact.

## Реальные незавершённые блокеры

- [ ] Нет подтверждённого успешного Windows Actions run для актуального `main`.
- [ ] Нет подтверждённого фактического запуска собранного portable EXE на пользовательском Windows-компьютере.
- [ ] Не проверен сквозной сценарий: трей → Блокнот → `Ctrl+Alt+1` → Unicode-вставка.
- [ ] Не подтверждены изменение/сохранение макроса, перезагрузка хоткеев и сохранность данных после перезапуска.
- [ ] Антивирусная реакция новой native-сборки не проверена; добавление приложения в исключения не является допустимым обходным путём.
- [ ] Цифровая подпись не выполнена и рассматривается как отдельный будущий внешний шаг.

## Критерий ближайшей рабочей версии

Версия не считается готовой, пока одновременно не подтверждены:

- [ ] GitHub Actions build завершён успешно.
- [ ] Получены versioned ZIP и SHA256.
- [ ] EXE запускается на реальном Windows 10/11 x64 без старых launcher-цепочек.
- [ ] Иконка WHAM появляется в системном трее.
- [ ] `Ctrl+Alt+1` вставляет ожидаемый многострочный Unicode-текст в Блокнот.
- [ ] Макрос можно создать, отредактировать и удалить.
- [ ] Изменение `macros.json`/редактора корректно перезагружает горячие клавиши.
- [ ] Перезапуск не удаляет пользовательские макросы.
- [ ] Portable-пакет не содержит `.cmd`, `.bat`, `.ps1`, `.vbs` и скрытых launcher-цепочек.

## Правило следующего инкремента

На каждом запуске выполняется максимум один небольшой законченный проверяемый инкремент и один логичный commit непосредственно в `main`. Если конкретного безопасного ценного изменения нет, фиктивный commit не создаётся.
